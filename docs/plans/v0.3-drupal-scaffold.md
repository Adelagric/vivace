# v0.3 — Drupal complet : drupal/core-composer-scaffold émulé

Statut : **exécuté** (2026-09-11) selon r2 — r1 réfuté par un sous-agent frais
(16 points, 6 majeurs) ; amendements en fin de document. Résultat : oracle
15 cas / arbres entiers / 0 divergence, fixture drupal 0 diff projet entier,
boot `vendor/bin/dr`, transitions.sh vert. Niveau **2** (fichiers
écrits hors vendor/ dans le projet de l'utilisateur, `.gitignore` modifiés,
appels à git ; une erreur = site Drupal qui ne démarre pas ou fichiers
utilisateur écrasés).

## 1. Cadrage

**Problème.** Un projet Drupal standard (`drupal/recommended-project`) verrouille
cinq plugins : `composer/installers` (émulé en v0.2), `symfony/runtime`
(émulé), `drupal/core-composer-scaffold`, `drupal/core-project-message`,
`drupal/core-recipe-unpack`. Aujourd'hui les trois derniers sont inconnus →
fallback : vivace n'apporte rien à Drupal. Fait vérifié sur Composer 2.10.3 :
`--no-scripts` ne coupe que les scripts du composer.json racine, **les
écouteurs des plugins s'exécutent** — le scaffold écrit `web/index.php`,
`web/.htaccess`, `web/sites/default/default.settings.php`, `web/autoload.php`,
`web/autoload_runtime.php`… et modifie la classmap de l'autoloader. Ces
fichiers sont ignorés par git dans un projet Drupal typique : sans émulation,
un `vivace install` sur un checkout ne donne pas un site qui démarre.

**Objectifs observables.**
1. Fixture `drupal` (squelette figé de `drupal/recommended-project` 11.4.6,
   lock résolu, 68 paquets) : `diff -r` **projet entier** contre
   `composer install --no-scripts` (plugins actifs) = 0 ligne, avec et sans
   autoloader, froid/chaud ; `harness/removal.sh` inclus ; boot =
   `php web/core/scripts/drupal --version` ou `php -r` chargeant
   `web/autoload.php` et `Drupal\DrupalInstalled::VERSIONS_HASH`.
2. Oracle de bout en bout du scaffold : pour une matrice de configurations
   synthétiques (plusieurs paquets avec `file-mapping` replace/append/skip,
   `overwrite: false`, `force-append`, `default`, `prepend`, surcharge entre
   paquets, `allowed-packages` récursif, `locations` personnalisées,
   `[project-root]`/`[web-root]`, `gitignore` true/false/absent, dépôt git ou
   non, fichier déjà présent identique/différent/tracké), le vrai plugin
   (source vendorée) piloté par php sur un projet temporaire et le port Rust
   produisent le même arbre de fichiers (contenu + liste), les mêmes
   `.gitignore` et le même `DrupalInstalled.php` — 0 divergence.
3. `core-project-message` (n'écoute que POST_INSTALL_CMD pour afficher un
   message) et `core-recipe-unpack` (POST_UPDATE_CMD / POST_CREATE_PROJECT_CMD
   seulement) classés BENIGN avec la preuve (événements écoutés, extraits de
   la source vendorée) — sans note stderr pour le message (pas d'effet disque).
4. Version du plugin : émulation seulement si l'**empreinte** de la source du
   plugin extraite dans le store (sha256 des fichiers PHP hors tests, triés)
   est dans la liste des empreintes portées ; sinon fallback nominatif
   (« drupal/core-composer-scaffold X: unported source »). Empreintes
   calculées pour tous les tags 11.x et 10.3+ dont la source est identique
   au 11.4.6 vendoré (à mesurer ; ceux qui diffèrent sont listés dans
   HANDOVER, pas devinés).
5. `vivace dump-autoload` applique aussi le `preAutoloadDump` (classmap +
   DrupalInstalled.php), comme Composer.

**Contraintes.** Aucun PHP exécuté à l'install ; git invoqué comme le plugin
(`check-ignore`, `ls-files --error-unmatch`, `rev-parse --show-toplevel`),
avec l'environnement `LANGUAGE=C` déjà utilisé. Source vendorée telle
qu'installée (`vendor/drupal/core-composer-scaffold` du projet de référence :
la copie GitHub du tag diffère des fichiers distribués — heredocs avec
commentaires). Une seule dépendance nouvelle : xxh3 (`xxhash-rust`, épinglée,
justifiée dans DECISIONS : `hash('xxh3')` de PHP = XXH3 64 bits, sans
équivalent std). Les `.gitignore` ne sont modifiés que selon la règle exacte
du plugin. Jamais d'écriture hors du projet (locations réalisées par
`realpath` → refus si hors racine).

**Non-objectifs.** `cweagans/composer-patches` (modifie le contenu des dists :
incompatible avec le store adressé par (nom, version, ref) sans une clé de
patch — chantier séparé, cadré après celui-ci). `symlink: true` du scaffold
(fallback). `drupal/legacy-scaffold-assets` (paquet Drupal 8, jamais dans un
lock moderne : traité comme tout paquet autorisé s'il est là). Le résolveur.

**Alternatives écartées.**
- Fallback total pour Drupal : c'est l'écosystème PHP avec le plus de sites
  et de pipelines CI lents ; c'est là que vivace sert.
- Émuler seulement `file-mapping` sans `preAutoloadDump` : autoloader
  différent de Composer (classmap et DrupalInstalled.php) → parité perdue et
  `DrupalInstalled::VERSIONS_HASH` absent → Drupal 11.2+ casse.
- Gating par tag comme installers : la source du scaffold est versionnée avec
  le cœur (une version par release Drupal) ; l'empreinte de source est plus
  juste et couvre automatiquement les releases à source identique.

## 2. Analyse de la source (core-composer-scaffold 11.4.6, telle qu'installée)

- `Plugin::getSubscribedEvents` : POST_INSTALL_CMD/POST_UPDATE_CMD → `postCmd`
  (= `Handler::scaffold()` puis `ensureAutoloadRuntimeFile`) ;
  POST_PACKAGE_INSTALL → collecte pour messages (`require` seulement) ;
  PRE_AUTOLOAD_DUMP → `preAutoloadDump` (statique).
- **AllowedPackages** : implicites `['drupal/legacy-scaffold-assets',
  'drupal/core']` + `extra.drupal-scaffold.allowed-packages` de la racine,
  récursif (chaque paquet autorisé ajoute ses propres allowed-packages),
  résolution dans le dépôt local (`findPackage($name, '*')` → paquets
  installés) ; la racine est ajoutée **en dernier** si elle a un
  file-mapping. Ordre d'insertion conservé (tableau PHP).
- **ScaffoldOptions** : défauts `allowed-packages: []`, `locations: {}` +
  `project-root: '.'`, `web-root: '.'`, `symlink: false`, `file-mapping: []`,
  `gitignore` absent = null.
- **Locations** : `locations() + ['web_root' => './']`, chaque valeur
  `ensureDirectoryExists` puis `realpath`. Interpolation `[token]` avec
  `[a-zA-Z0-9._-]+`, `strtr` ; token inconnu → `$default` ('' pour les
  destinations).
- **OperationData** : valeur `false` → skip ; `true` → exception ; vide →
  exception ; chaîne → `{path}` ; `mode` absent + (`append`|`prepend`) →
  append ; défauts `mode: replace, prepend/append/default: null,
  overwrite: true`. `overwrite()` = `!empty`, `forceAppend()` = default
  présent ou `!empty(force-append)`.
- **OperationFactory** : replace exige `path` ; source = `<install path du
  paquet>/<path>` (racine : `getcwd()`), doit exister et ne pas être un
  répertoire ; append sans contenu prepend/append → SkipOp.
- **ScaffoldFileCollection** : par paquet dans l'ordre, par destination ; une
  destination déjà vue → l'op précédente devient SkipOp (message), la
  nouvelle reçoit `scaffoldOverExistingTarget(prev op)` (AppendOp :
  `originalContents = prev->contents()`) ; sinon `scaffoldAtNewLocation`
  (AppendOp : `managed = false` ; sans force-append → Skip ; fichier absent
  sans default → Skip ; fichier contenant déjà append/prepend → Skip ; sinon
  `originalContents = fichier`). `checkUnchanged` : op.contents() ==
  contenu actuel du fichier → filtré (non réécrit) ; `filterFiles` retire
  aussi les projets sans contenu (messages seulement).
- **ReplaceOp::process** : `overwrite === false` et fichier existant → skip
  (résultat non managé) ; sinon remove + ensureDirectoryExists + écriture ;
  perms d'origine du fichier restaurées.
- **AppendOp** : `prepend . "\n" . original . "\n" . append` (original =
  `default` si vide) ; résultat managé ssi `managed` (pas nouvelle
  location).
- **Autoload de référence** : `web-root/autoload.php` si absent ou non
  tracké par git ; contenu = heredoc (avec commentaire) +
  `findShortestPath(<web-root>/autoload.php, <vendor realpath>/autoload.php)`
  sans `./` initial ; idem `autoload_runtime.php` (Plugin::
  ensureAutoloadRuntimeFile ne le crée que s'il n'existe pas ; Handler le
  régénère s'il n'est pas tracké).
- **ManageGitIgnore** : activé si option `gitignore` définie (sa valeur),
  sinon ssi `git rev-parse --show-toplevel` réussit ET `git check-ignore
  vendor` réussit. Pour chaque résultat : si non ignoré, non tracké et
  managé → entrée `/<basename>` dans `<realpath(dirname)>/.gitignore`
  (entrées triées, ajoutées à la fin, newline assuré avant).
- **preAutoloadDump** : si `symfony/http-foundation` installé → 7 fichiers
  ajoutés à la classmap racine (`<vendor-dir>/symfony/http-foundation/…`,
  chemin relatif `vendor/...`), `symfony/http-kernel` → 3, `symfony/
  dependency-injection` → 1, `psr/container` → 1 ; écrit
  `<vendor realpath>/drupal/DrupalInstalled.php` (template) et l'ajoute à
  la classmap. Hash = xxh3 de `concat(sorted(uniqueName-sourceRef|)) +
  root uniqueName-sourceRef` sur `getPackages()` du dépôt local (alias
  compris : `name-9999999-dev-ref`), uniqueName = `name-version_normalized`.
- Événements sous `--no-scripts` : tous exécutés (vérifié :
  `EventDispatcher::doDispatch` ne filtre que `getScriptListeners`).

## 4. Amendements r2 (après méta-analyse)

1. **Version exécutée ≠ version du lock.** Composer charge le plugin installé
   (vendor/) et `Handler` est instancié depuis l'ancien code au premier
   POST_PACKAGE_INSTALL : lors d'une montée de version du plugin, le scaffold
   tourne en mode mixte. Gate : empreinte de la dist du lock ET de la copie
   installée dans vendor/ (si présente) ; différentes → fallback nominatif.
   Cas harness « upgrade du plugin » ajouté (vendor posé à N-1, lock à N).
2. **Plan pur puis application.** `scaffold::plan(profile, extras, chemins
   sources (store), état disque) -> Result<Plan, Issue>` calculé après le
   fetch vers le store et **avant** toute suppression (`installer.rs`
   réordonné : removals après le fetch) ; issue → erreur typée → la CLI
   exec Composer, vendor/ intact. `apply(plan)` après l'autoloader.
3. **allow-plugins / --no-plugins** appliqués au scaffold via le même
   `plugin_verdict` que installers (rendu `pub(crate)`) ; « Unlisted » →
   issue ; `--no-plugins` → rien ; idem `dump-autoload`.
4. **Destination existante non fichier régulier** (répertoire, lien) →
   refus (Composer effacerait récursivement) ; parent qui est un fichier →
   refus. Sources : `realpath` hors du répertoire d'installation du paquet →
   refus. Destinations : sous la racine canonique **ou** sous le realpath
   d'une location déclarée par la racine (docroot symlinké légitime).
5. **`--no-autoloader`** : pas de `preAutoloadDump` (comme Composer) ;
   `dump-autoload` le rejoue depuis l'état installé. `diff-vendor.sh` ne
   filtre plus que `vendor/autoload_runtime.php`.
6. **Boot** = `php vendor/bin/dr --version` (le script de core/scripts ne
   trouve pas vendor/ dans un recommended-project) + lecture de
   `VERSIONS_HASH` via `web/autoload.php`. `VERSIONS_HASH` n'est pas requis
   au boot (class_exists) : le port de preAutoloadDump se justifie par la
   parité, pas par le démarrage.
7. **Clé de collision = chaîne brute** de destination (non interpolée),
   résultats indexés pareil : port à l'identique (deux entrées `/index.php`
   possibles dans un .gitignore, comme le plugin). `allowed-packages` : DFS
   pré-ordre, premier vu conservé, `findPackage` insensible à la casse.
8. **Hash** : racine = alias si `branch-alias` matche (`root_version::
   branch_alias`), référence vide si version explicite/COMPOSER_ROOT_VERSION ;
   `findPackage(name, '>' '')` ne matche pas une version `dev-*` sans alias
   numérique → entrées classmap omises dans ce cas ; alias comptés dans
   `getPackages()` (alias puis paquet, ordre installed.json pour le profil
   non trié).
9. **Racine canonicalisée** pour le scaffold (`getcwd()` physique).
10. **git** : binaire absent = échec (pas d'erreur propagée) ; `gitignore:
    true` explicite écrit même sans git ; cas « git absent » dans l'oracle.
11. **Oracle simplifié** : mini-projets temporaires avec dépôts `path`
    (symlink: false) — référence `composer install --no-scripts` avec le
    plugin, côté vivace `composer install --no-scripts --no-plugins` puis
    `scaffold::plan/apply` + `pre_autoload_dump` en bibliothèque ; diff des
    arbres hors vendor/composer + comparaison de DrupalInstalled.php et des
    entrées classmap. Trois versions du plugin (11.4.6, 11.3.2, 11.2.14)
    pour couvrir les profils.
12. **Profil par empreinte** dès le départ : 4 niveaux (0 : file-mapping +
    autoload.php ; 1 : + preAutoloadDump hash non trié ; 2 : hash trié ;
    3 : + autoload_runtime.php), 11 empreintes → 120 versions (10.3.0 →
    12.0.0-alpha1) couvertes. `drupal/legacy-project` (core-vendor-hardening)
    reste en fallback : dit dans README.
13. Hooks `pre/post-drupal-scaffold-cmd` cités dans la note « scripts non
    exécutés » du README.
14. `web/autoload.php` et `autoload_runtime.php` réécrits à chaque run
    (parité ; la note perf est retirée).
15. Matrice oracle enrichie des cas listés par la méta (overwrite false +
    absent, mode absent avec path+append, overwrite "false" chaîne, prepend
    vide, contenu "0", skip puis append avec default, .gitignore scaffoldé,
    aucun paquet autorisé, web-root "web/", git absent).

## 5. Revue indépendante (sous-agent, 2026-09-11)

Cinq majeurs corrigés avant commit : (1) `dump-autoload --no-dev` hachait
`lock ∩ dev_mode` alors que Composer lit l'état installé (divergence prouvée
sur mini-projet) → état installé ; (2) les metapackages étaient exclus de la
liste vue par `findPackage`, cassant la récursion des `allowed-packages`
(prouvé, cas ajouté à l'oracle) → présents avec un chemin vide ; (3) le
harness copiait un `web/` déjà scaffoldé et le committait : tout était
« tracké et inchangé », le scaffold n'était pas prouvé → sorties d'install
exclues de la copie (web/, wp-content/, recipes/, .editorconfig,
.gitattributes) ; (4) fichiers en lecture seule (`.htaccess` 0444,
`sites/default` 0555) → port de `makeWritable` + remove + restauration des
perms ; (5) `transitions.sh` hachait des noms de fichiers → contenus et
répertoires. Mineurs corrigés : `$scaffold_results[]` ajouté (deux entrées
`.gitignore` possibles pour autoload.php), `!empty("0")`, `gitignore: null`,
`dump-autoload` avec plugin non listé → erreur comme Composer, formulation
« 1 113 fichiers ». Non corrigés (documentés) : `git ls-files` lancé depuis
la racine et non depuis le docroot (dépôt git imbriqué), répertoires de
`locations` créés avant un refus ultérieur, contrôle « sous la racine »
lexical comme PHP.
